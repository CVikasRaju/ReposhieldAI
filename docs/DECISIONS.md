# Decisions

Deviations from the specification pack and the reasoning behind each. Newest last.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-18 | The specification files were moved from `docs/docs/` to `docs/` and the empty nested directory removed. | Every document and `AGENTS.md` refers to `docs/01-...` through `docs/09-...`; the extra nesting was a packaging artifact. |
| 2026-10-18 | The MCP SDK is pinned to `mcp>=1.2,<2.0`. | The specification requires FastMCP. The installed 2.3 SDK renamed FastMCP to `MCPServer`; pinning 1.x keeps the documented API. Verified against the installed 1.30.0 source. |
| 2026-10-18 | No Faker dependency was added. Seeded customer data is produced with `random.Random(42)` and small local generators. | Faker is not in the AGENTS.md dependency list. The stdlib generator is deterministic and satisfies the "Faker seed 42" intent without a new dependency. |
| 2026-10-18 | The seeded workspace uses the documented *fake* example secrets verbatim and is gitignored. | `docs/08` specifies the exact `.env` contents and marks all values fake. The workspace is generated at seed time and never committed, so GitHub push protection cannot flag the repository. |
| 2026-10-18 | `ALLOWED` is added as a display-only reason code with the template "The action is within what the agent was asked to do." | Every event needs a plain-language sentence, but `docs/03` section 7 has no generic allow template. The code is never produced as a policy rule. |
| 2026-10-19 | `backend/models/content_model.joblib` was regenerated with `make train-model`. | The committed artifact predated the sanitized training data, so the first rerun changed the file. Training already pins `random_state=7` for the split and the estimator; two consecutive reruns now produce byte-identical output, so the committed model matches the current training data. |
| 2026-10-19 | The optional watchdog (`backend/watchdog/watchdog.py`) was repaired: it now builds valid event records and scans children with `psutil`. It is still not started by the gateway. | The module passed tuples and a float where enums and an ISO timestamp were expected, and swallowed the resulting validation error, so it could never log an alert. It remains the optional C11 local-mode layer, while Docker supplies the enforcement boundary. |
| 2026-10-19 | `RS_MCP_ALLOWED_HOSTS` (and `RS_MCP_ALLOWED_ORIGINS`) were added to let the MCP listener accept the container Host header `gateway:8001`. | The MCP SDK's DNS-rebinding guard rejects unknown Host headers, so the sandboxed agent could not initialize a session in Docker even though the same client works on localhost. The allowlist is explicit, set only by `docker-compose.yml`, and unset keeps the SDK's localhost-only default. |
| 2026-10-19 | The gateway container runs as root while the agent container runs as the non-root `agent` user. The agent sandbox idles (`sleep infinity`) and the demo is run with `docker compose exec -T agent python simulated_agent.py`. | The gateway must write `workspace/` and `data/` through bind mounts owned by the host user; a fixed container uid cannot write them on Linux hosts. The agent has no mounts, so it stays non-root. Idling avoids the demo's kill-switch locking the session and the restart policy replaying it in a loop. |
| 2026-10-19 | The dashboard uses the installed React 19 and Tailwind 4.3 with the official `@tailwindcss/vite` plugin and `@import "tailwindcss"`, plus `zustand` for state and `@types/cytoscape` for the graph types. `tailwind.config.js` was removed because Tailwind 4 configures itself from the source files. | `AGENTS.md` names React 18 and Tailwind; the scaffold already pinned React 19 and Tailwind 4, and downgrading would churn the scaffold for no product benefit. `docs/07` requires Zustand and Cytoscape, and the Tailwind 4 Vite plugin is the documented way to get a non-empty CSS bundle (the previous empty bundle came from using v3 directives with v4). |
| 2026-10-19 | The hand-written evaluation dataset was corrected after the first full run: `secret_01` expects BLOCK (the `**/.env*` protect rule blocks the read), and `cmd_10`, `cmd_12`, `cmd_15`, `cmd_21`, `cmd_dos_02`, `cmd_dos_05` expect BLOCK (the command gateway blocks shell metacharacters and paths outside the workspace). No other labels were changed; the remaining differences are reported as failure cases in `eval/results/results.md`. | These seven labels contradicted documented, invariant-level behaviour (AGENTS.md invariants 9 and 10, `docs/04` section on the command gateway, and the `protect` block rule in `.aishield`). The labels were wrong about the spec, not the system; every other mismatch was left in place and reported honestly. |
| 2026-10-19 | `eval/results/` was regenerated with `make eval` in an environment where the POSIX command tools exist, replacing the run committed in `f0b14f7` (detection 0.7748). | That run happened in a Windows shell without `cat`, `head`, `grep`, `wc`, `tail` or `ls` on PATH: 19 command items ended with `ACTION_FAILED` instead of executing, and `pair_12a` scored ALLOW instead of MASK. The dataset, thresholds and code were unchanged; rerunning the same commit twice in a working environment produced 0.7815 both times. Both measurements are recorded (see `docs/PROGRESS.md` limitations) so the difference is explained rather than hidden. |
